개념 이해
Git과 GitHub, 무엇이 다를까?
버전 관리의 개념과 두 도구의 역할을 이해합니다
🌿
Git
내 컴퓨터에 설치하는 버전 관리 도구. 파일의 변경 이력을 추적하고 이전 상태로 되돌릴 수 있습니다.
🐙
GitHub
Git 저장소를 인터넷에 올려두는 클라우드 플랫폼. 다른 사람과 협업하거나 작업물을 공개할 수 있습니다.
Git은 혼자서도 사용할 수 있고, GitHub 없이도 동작합니다
GitHub는 Git이 있어야 의미가 있습니다 — Git이 먼저입니다
비유: Git = 일기장, GitHub = 일기장을 올려두는 클라우드

Git 설치
Git 설치하기
Windows 환경에서 Git을 설치하고 기본 설정까지 완료합니다
1
Git 공식 사이트 접속
브라우저에서 git-scm.com 접속 → 운영체제에 맞는 설치 파일 자동 감지
2
설치 파일 다운로드 및 실행
Download for Windows 클릭 → .exe 파일 실행 → 기본값 유지하며 Next 진행
3
설치 확인
Git Bash 실행 후 버전 확인
git --version
4
사용자 정보 등록 (최초 1회)
커밋할 때 기록될 이름과 이메일을 설정합니다
git config --global user.name "이름" git config --global user.email "이메일"
💡
설치 중 기본값(Next)으로만 진행해도 괜찮습니다. 단, 기본 에디터 선택 시 Visual Studio Code를 선택하면 나중에 편리합니다.

Git Bash
Git Bash로 문서 만들기
터미널 명령어로 폴더와 파일을 만들고 Git 저장소를 초기화합니다
폴더 · 파일 명령어
mkdir 폴더명
새 폴더 만들기
cd 폴더명
폴더 안으로 이동
cd ..
상위 폴더로 이동
touch 파일명.txt
빈 파일 만들기
ls
현재 폴더 내용 확인
Git 초기화
git init
현재 폴더를 Git 저장소로 초기화
git status
현재 상태 확인 (변경된 파일 목록)
ls -a
.git 폴더 포함 숨김 파일까지 확인
$ mkdir my-project && cd my-project
$ git init
Initialized empty Git repository in .git/
$ touch README.md && git status
Untracked files: README.md
💡
git init 을 하면 폴더 안에 숨김 폴더 .git 이 생깁니다. 이 폴더가 모든 버전 정보를 저장하는 핵심입니다. 절대 삭제하지 마세요!

add · commit
add 및 commit 하기
파일 변경사항을 Git에 기록하는 핵심 두 단계를 익힙니다
작업 공간
Working Directory
파일을 편집하는 곳
git add
→
임시 저장소
Staging Area
커밋할 파일을 모아두는 곳
git commit
→
로컬 저장소
Repository
버전이 기록되는 곳
주요 명령어
git add 파일명
특정 파일을 Staging Area에 올리기
git add .
변경된 모든 파일을 한번에 올리기
git commit -m "메시지"
메시지와 함께 현재 상태를 기록 (버전 생성)
git log
지금까지의 커밋 이력 확인
$ git add .
$ git commit -m "첫 번째 커밋"
[main (root-commit) a1b2c3d] 첫 번째 커밋
1 file changed, 0 insertions(+)
💡
커밋 메시지는 나중에 봤을 때 무엇을 했는지 알 수 있도록 구체적으로 적으세요. "수정함" 보다는 "로그인 버튼 색상 변경"처럼요.

GitHub Push
GitHub 로그인 후 Push하기
로컬 저장소의 내용을 GitHub 원격 저장소에 올립니다
내 컴퓨터
로컬 저장소
commit 완료 상태
git push
→
인터넷
GitHub 원격 저장소
누구나 접근 가능
GitHub 레포 만들기
1
GitHub 로그인
github.com 접속 후 로그인
2
새 레포지토리 생성
+ 버튼 → New repository → 이름 입력 → Create
3
HTTPS 주소 복사
생성된 레포의 주소 복사
Push 명령어
1
원격 저장소 연결
git remote add origin 주소
2
브랜치 이름 설정
git branch -M main
3
Push 실행
git push -u origin main
💡
두 번째 push부터는 git push 만 입력하면 됩니다. -u 옵션은 최초 연결 시 한 번만 필요합니다.

브랜치
브랜치 기초 익히기
원본을 건드리지 않고 독립된 작업 공간을 만드는 방법을 익힙니다
main
C1
C2
C3
C6
← merge
feature
C4
C5
브랜치 명령어
git branch
브랜치 목록 확인
git branch 이름
새 브랜치 만들기
git switch 이름
해당 브랜치로 이동
git switch -c 이름
만들면서 바로 이동
병합 명령어
git merge 브랜치명
현재 브랜치에 합치기
git branch -d 이름
병합 완료된 브랜치 삭제
git log --oneline
한 줄로 커밋 이력 확인
💡
main은 항상 안정된 상태로 유지하고, 새 작업은 별도 브랜치에서 하는 것이 좋습니다. 브랜치는 복사본이 아니라 작업 방향이 나뉘는 것입니다.
