개념 이해
Git과 GitHub, 무엇이 다를까?
버전 관리의 개념과 두 도구의 역할을 이해합니다
🌿
Git
내 컴퓨터에 설치하는 버전 관리 도구. 파일의 변경 이력을 추적하고 이전 상태로 되돌릴 수 있습니다.
🐙
GitHub
Git 저장소를 인터넷에 올려두는 클라우드 플랫폼. 다른 사람과 협업하거나 작업물을 공개할 수 있습니다.
Git은 혼자서도 사용할 수 있고, GitHub 없이도 동작합니다
GitHub는 Git이 있어야 의미가 있습니다 — Git이 먼저입니다
비유: Git = 일기장, GitHub = 일기장을 올려두는 클라우드

Git Bash
Git Bash 기본 명령어
폴더와 파일을 다루는 기본 명령어를 익히고 저장소를 초기화합니다
폴더 · 이동 명령어
pwd
현재 내가 있는 위치 확인
ls
현재 폴더 내용 목록 확인
ls -a
숨김 파일(.git 등)까지 전부 확인
mkdir 폴더명
새 폴더 만들기
cd 폴더명
해당 폴더로 이동
cd ..
상위 폴더로 이동
Git 초기화
git init
현재 폴더를 Git 저장소로 초기화 (.git 폴더 생성)
git status
현재 상태 확인 — 가장 자주 쓰는 명령어!
⚠️
git init 후 생기는 .git 폴더는 절대 삭제하지 마세요! 모든 버전 정보가 여기에 저장됩니다.
$ mkdir my-project # 폴더 생성
$ cd my-project # 폴더로 이동
$ git init
Initialized empty Git repository in /my-project/.git/
$ ls -a
. .. .git ← .git 폴더가 생겼어요!

문서 만들기
Git Bash로 문서 만들기
touch, echo, cat 명령어로 파일을 만들고 내용을 입력합니다
파일 만들기 3가지 방법
① touch — 빈 파일 만들기
touch README.md
→ 내용이 없는 빈 파일 생성. 나중에 에디터로 내용 입력
② echo — 내용을 바로 입력하면서 파일 만들기 ⭐ 가장 빠른 방법!
echo "안녕하세요" > hello.txt
echo "두 번째 줄입니다" >> hello.txt
→ > 는 새로 쓰기 (덮어씀)  |  >> 는 이어서 쓰기 (추가)
③ cat — 파일 내용 확인하기
cat hello.txt
→ 파일 내용을 터미널에 바로 출력
$ echo "# 나의 첫 번째 프로젝트" > README.md
$ echo "작성자: 홍길동" >> README.md
$ echo "시작일: 2025-01-01" >> README.md
$ cat README.md
# 나의 첫 번째 프로젝트
작성자: 홍길동
시작일: 2025-01-01
💡
> 와 >> 의 차이를 꼭 기억하세요!   > 는 기존 내용을 지우고 새로 씁니다. >> 는 기존 내용 아래에 추가합니다. 실수로 > 를 쓰면 내용이 사라질 수 있어요!

add · commit
add 및 commit 하기
파일 변경사항을 Git에 기록하는 핵심 두 단계를 익힙니다
작업 공간
Working Directory
파일을 편집하는 곳
git add
→
임시 저장소
Staging Area
커밋할 파일을 모아두는 곳
git commit
→
로컬 저장소
Repository
버전이 기록되는 곳
주요 명령어
git add 파일명
특정 파일을 Staging Area에 올리기
git add .
변경된 모든 파일을 한번에 올리기 (가장 많이 씀)
git commit -m "메시지"
메시지와 함께 현재 상태를 기록 (버전 생성)
git log
지금까지의 커밋 이력 확인
git log --oneline
커밋 이력을 한 줄로 간략하게 확인
$ git add .
$ git commit -m "README 파일 추가"
[main (root-commit) a1b2c3d] README 파일 추가
1 file changed, 3 insertions(+)
💡
커밋 메시지는 구체적으로 적으세요. "수정함" 보다는 "README에 작성자 정보 추가"처럼요. 나중에 이력을 볼 때 큰 도움이 됩니다.

초보자 필수
.gitignore — 올리면 안 되는 파일 관리
GitHub에 올리면 안 되는 파일을 Git이 무시하도록 설정합니다
왜 필요한가?
🚫
비밀번호 · API 키 파일
.env 파일에 담긴 비밀 정보가 공개되면 매우 위험!
⚠️
node_modules 폴더
수천 개 파일이 들어있어 올리면 느리고 용량 낭비
⚠️
운영체제 자동 생성 파일
.DS_Store(Mac), Thumbs.db(Windows) 등 불필요한 파일
.gitignore 만들기
터미널에서 직접 만들기
echo ".env" > .gitignore
echo "node_modules/" >> .gitignore
echo ".DS_Store" >> .gitignore
.gitignore 내용 예시
# 환경변수
.env

# 의존성 폴더
node_modules/

# 운영체제 파일
.DS_Store
Thumbs.db
💡
gitignore.io 사이트에서 프로젝트 종류(Python, Node, React 등)를 입력하면 .gitignore 내용을 자동으로 만들어줍니다!

GitHub Push
GitHub 로그인 후 Push하기
로컬 저장소의 내용을 GitHub 원격 저장소에 올립니다
내 컴퓨터
로컬 저장소
commit 완료 상태
git push
→
인터넷
GitHub 원격 저장소
누구나 접근 가능
GitHub 레포 만들기
1
GitHub 로그인
github.com 접속 후 로그인
2
새 레포지토리 생성
+ 버튼 → New repository → 이름 입력 → Create
3
HTTPS 주소 복사
생성된 레포의 주소 복사
Push 명령어
1
원격 저장소 연결
git remote add origin 주소
2
브랜치 이름 설정
git branch -M main
3
Push 실행
git push -u origin main
💡
두 번째 push부터는 git push 만 입력하면 됩니다. -u 옵션은 최초 연결 시 한 번만 필요합니다.

브랜치
브랜치 기초 익히기
원본을 건드리지 않고 독립된 작업 공간을 만드는 방법을 익힙니다
main
C1
C2
C3
C6
← merge
feature
C4
C5
브랜치 명령어
git branch
브랜치 목록 확인 (* 가 현재 위치)
git branch 이름
새 브랜치 만들기
git switch 이름
해당 브랜치로 이동
git switch -c 이름
만들면서 바로 이동 (가장 많이 씀)
병합 명령어
git merge 브랜치명
현재 브랜치에 합치기
git branch -d 이름
병합 완료된 브랜치 삭제
git log --oneline
한 줄로 커밋 이력 확인
💡
main은 항상 안정된 상태로 유지하고, 새 작업은 별도 브랜치에서 하는 것이 좋습니다. 브랜치는 복사본이 아니라 작업 방향이 나뉘는 것입니다.
