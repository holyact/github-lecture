VSCode
VSCode 활용하기
터미널 대신 VSCode에서 Git을 시각적으로 관리합니다
Git Bash vs VSCode
🖥
Git Bash (터미널)
명령어를 직접 입력. 정확하지만 외워야 함
💙
VSCode (GUI)
클릭으로 add·commit·push 가능. 변경 파일을 색으로 표시
VSCode Git 패널 위치
1
소스 제어 패널 열기
왼쪽 사이드바 분기 아이콘 클릭 (Ctrl+Shift+G)
2
변경 파일 확인
수정된 파일이 목록에 표시됨 (M=수정, U=새파일)
3
+ 버튼으로 add
파일 옆 + 클릭 → Staged Changes로 이동
4
메시지 입력 후 커밋
상단 입력창에 메시지 → Commit 버튼
💡
VSCode 하단 터미널(Ctrl+`)을 열면 Git Bash 명령어도 함께 사용할 수 있어요. GUI와 터미널을 함께 쓰면 가장 효율적입니다.

브랜치 활용
브랜치 활용 — 수정하고 합치기
실제 개발 흐름처럼 브랜치를 만들고 기능을 추가한 뒤 main에 합칩니다
실습 시나리오
1
main 브랜치 확인
현재 main에서 시작. 안정된 상태 유지
2
새 기능 브랜치 생성
git switch -c add-feature
3
기능 추가 후 커밋
코드 수정 → add → commit
4
main으로 돌아와 merge
git switch main → git merge add-feature
5
브랜치 삭제 후 push
git branch -d add-feature → git push
터미널 실습
$ git switch -c add-feature
Switched to a new branch 'add-feature'
# 코드 수정 후
$ git add . && git commit -m "기능 추가"
$ git switch main
$ git merge add-feature
Updating a1b2c3d..e4f5g6h
$ git branch -d add-feature
$ git push
💡
기능 하나 = 브랜치 하나 원칙을 지키면 나중에 문제가 생겼을 때 해당 브랜치만 되돌리면 됩니다. main은 항상 동작하는 상태로 유지하세요.

충돌 해결
충돌 해결 연습하기
같은 파일을 두 브랜치에서 수정했을 때 생기는 충돌을 해결하는 방법을 익힙니다
⚠️ 충돌 발생 시 파일 모습
<<<<<<< HEAD
main 브랜치의 내용
=======
feature 브랜치의 내용
>>>>>>> feature
✅ 해결 후 파일 모습
원하는 내용만 남기고
충돌 표시 기호를 모두 삭제
# 그 다음:
git add .
git commit -m "충돌 해결"
충돌 해결 단계
1
충돌 파일 확인
git status 로 충돌난 파일 목록 확인 (both modified 표시)
2
파일 열어서 직접 수정
VSCode에서 충돌 표시 기호 제거 후 원하는 내용만 남기기. VSCode는 Accept Current / Accept Incoming 버튼 제공
3
수정 후 다시 커밋
git add . → git commit -m "충돌 해결"
⚠️
충돌은 실수가 아닙니다! 협업에서 자연스럽게 발생하는 상황이에요. 당황하지 말고 충돌 파일을 열어 <<<, ===, >>> 기호만 찾아서 정리하면 됩니다.
